# IkonSM build spec (internal contract between modules)

Read `PLAN.md` for the product. This file is the **contract**: each module owner
implements exactly these exports, so modules built in parallel fit together.
Shared types live in `shared/types.ts` (do not change existing fields without
updating every user; adding optional fields is fine).

Stack (pinned in package.json, verified working tonight):
agents 0.32.0 · @anthropic-ai/sdk 1.4.0 · hono 4.13 · postal-mime 4.2 · unpdf 2.1 ·
fflate 0.8 · zod 4.6 · React 19.3 · Vite 8 + @cloudflare/vite-plugin 1.67 · Tailwind 4.3 ·
vitest 5.1 + @cloudflare/vitest-plugin 1.5 · TypeScript 7 (native tsc) · wrangler 4.156.

Hard rules
- TypeScript strict. `verbatimModuleSyntax` is on: use `import type` for types.
- Imports between worker files use relative paths **with `.ts` extension omitted**
  (bundler resolution), e.g. `import { x } from "../ai/triage"`.
- `Env` is the global type generated by `wrangler types` into
  `worker-configuration.d.ts` plus secrets from `.dev.vars`
  (`ANTHROPIC_API_KEY`, `HUB_PASSCODE`, `SESSION_SECRET`, `CF_ACCOUNT_ID`, `AI_GATEWAY_ID`, `CF_AIG_TOKEN` — all strings, may be EMPTY: treat "" as unset).
  Bindings: `PropertyAgent`, `ChiefOfStaffAgent` (DO namespaces), `VAULT` (R2), `EMAIL` (SendEmail), `AI` (Workers AI), `LOGIN_LIMITER` (rate limiting: 10 logins/min per CF-Connecting-IP),
  vars `APP_NAME`, `COMPANY_NAME`, `EMAIL_DOMAIN`, `LLM_PROVIDER`, `WORKERS_AI_MODEL`, `MODEL_AGENT`, `MODEL_TRIAGE`, `AUTH_REQUIRED`.
- LLM provider (`aiProvider(env)` in `worker/ai/client.ts`): `LLM_PROVIDER` = auto | anthropic | gateway | workers-ai | off.
  auto = `ANTHROPIC_API_KEY` → Claude direct; else `CF_AIG_TOKEN` + `CF_ACCOUNT_ID` + `AI_GATEWAY_ID` → Claude via
  Cloudflare AI Gateway unified billing (no Anthropic key); else off. Workers AI only when set explicitly (lighter: no tools).
  Results carry `engine` ("claude" | "workers-ai" | "rules"/"template") plus `model` and `provider`; label them with `shared/engines.ts`.
- No `@callable` decorators. The browser never calls agent methods over the
  websocket; all mutations go through authenticated Hono `/api/*` routes that call
  the agents via Durable Object RPC (`getAgentByName(env.PropertyAgent, id)`).
  The websocket (`/agents/property-agent/<id>`) is **read-only live state**.
- Inbound email/SMS content is **untrusted data**. It must never trigger an
  outbound send by itself. Every outbound email is an `Approval` that a logged-in
  human approves. Recipients of an approved email are restricted to: the thread's
  original sender, or a contact stored on that building. On a simulated thread the
  typed sender only counts as "original sender" on a reserved test domain
  (example.com/.net/.org, *.example, *.test, *.invalid, *.localhost).
- Emailed attachments are filed (07 Correspondence, `uploadedBy: "email:<sender>"`) but are
  **not building records**: `searchDocs` leaves them out unless `{ includeEmailed: true }`
  (only the vault search screen, which labels them), so triage, drafts and chat never quote them.
- Inbound email limits: an Email Routing retry (same Message-ID) is ignored before attachments are
  filed; past 10 emails/sender/day or 200/building/day (Perth day) mail is triaged by the rules
  engine only, nothing is drafted automatically and attachments are not filed.
- A From address that fails SPF/DKIM/DMARC (Authentication-Results), or without those headers does
  not match the envelope sender's domain, is `senderVerified: false`: never matched to a contact's
  name/lot, never merged into a thread by subject, and badged "Unverified sender".
- WA terminology: "strata company", "council", "contributions"/levies,
  "scheme by-laws", "administrative fund"/"reserve fund". Never "owners
  corporation", "strata committee", "sinking fund", "capital works fund",
  "licensed strata manager", "Form 28/29".
- Everything works with **no `ANTHROPIC_API_KEY`** (tests and local dev run
  without it): triage falls back to `engine: "rules"`, drafts to
  `engine: "template"`, chat answers with an "AI offline" message that still
  shows document search results. Never pretend the rules engine is Claude.
- Sample/demo content is always labelled `sample: true` and its text starts
  with `SAMPLE DOCUMENT - replace with the real ... ` so nobody mistakes it for real records.
- IDs: `crypto.randomUUID()`. Timestamps: ISO strings (`new Date().toISOString()`).

## Module A: `worker/agents/property-agent.ts` (+ `worker/agents/property-schema.ts`)

`export class PropertyAgent extends Agent<Env, PropertyState>` (from `agents`).
One instance per scheme, named by property id (`"sp-26707"`). Its SQLite is the
building's "computer": tables `threads, messages, tickets, approvals, docs,
doc_chunks (+ FTS5 virtual table doc_fts tokenize='porter unicode61'), contacts,
activity, memory, chat (UI chat log), llm_history (Anthropic MessageParam JSON, append-only), meta`.
Create tables idempotently in `onStart`.

- `initialState`: empty counts, `profile: null`, `aiOnline: false`, `busy.active=false`, `recentActivity: []`, `version: 0`.
- `shouldConnectionBeReadonly() { return true }` and `validateStateChange(_, source)` throws if `source !== "server"`.
- `onRequest` → 404 JSON (`{error:"use /api"}`).
- After every mutation call a private `touch()` that recomputes counts, bumps
  `version`, refreshes `recentActivity` (last 25) and `setState`s.

Public RPC methods (all `async`, return plain JSON-serialisable values):

```ts
init(profile: PropertyProfile): Promise<void>                // idempotent; stores profile in meta
getProfile(): Promise<PropertyProfile | null>
getOverview(): Promise<PropertyOverview>
getStats(): Promise<{ profile: PropertyProfile | null; counts: PropertyCounts; lastActivityAt: string | null; p1Threads: Thread[]; pendingApprovals: Approval[] }>

ingestMessage(input: InboundInput, opts?: { process?: "now" | "background" }): Promise<{ threadId: string; messageId: string }>
  // Threads by inReplyTo/references → existing thread's messageIds, else by same sender + same normalised subject within 14 days, else new thread.
  // Logs activity "message_in"/"email_in". Then runs processThread(threadId):
  //   "now" (default) awaits it; "background" uses this.queue("processThreadTask", { threadId }).
processThreadTask(payload: { threadId: string }): Promise<void>   // queue callback → processThread
processThread(threadId: string): Promise<void>
  // 1) triage via ai/triage.triageMessage (context = top doc search hits for the message)
  // 2) if category=maintenance|insurance and priority P1|P2 → create Ticket (status "new", assigneeRole from triage.allocateTo[0] mapped, contractorId = best matching contact by trade + afterHours for P1)
  // 3) if triage.replyNeeded && !suspectedPromptInjection && category!=="spam" → draft reply via ai/drafting.draftReply → Approval(kind "send_email") to the sender
  // 4) if a contractor contact with email was selected for a P1/P2 ticket → second Approval(kind "dispatch_contractor") email to the contractor (work order details, access/safety info from docs)
  // thread.status becomes "awaiting_approval" if approvals were created, else "triaged". busy state shown while working.
retriage(threadId: string): Promise<Triage>
draftReply(threadId: string, instructions: string | null, actor: string): Promise<Approval>

listThreads(filter?: { status?: ThreadStatus | "open" }): Promise<Thread[]>   // newest first; "open" = not closed
getThread(threadId: string): Promise<{ thread: Thread; messages: Message[]; approvals: Approval[]; ticket: Ticket | null } | null>
closeThread(threadId: string, actor: string): Promise<void>

listApprovals(status?: ApprovalStatus): Promise<Approval[]>
decideApproval(approvalId: string, decision: ApprovalDecision, actor: string): Promise<Approval>
  // approve: validate recipient (thread sender or building contact email) → email/outbound.sendApprovedEmail(...) → add outbound Message to thread, thread.status "replied", ticket → "assigned" for dispatch. Errors → status "failed" with result text (never throw to caller for send errors).
  // reject: status "rejected". Only "pending" approvals can be decided (else throw Error("Approval already decided")).

listTickets(): Promise<Ticket[]>
createTicket(input: TicketInput, actor: string): Promise<Ticket>   // number = WO-<spNumber>-<4-digit seq>
updateTicket(id: string, patch: Partial<TicketInput> & { status?: TicketStatus }, actor: string): Promise<Ticket>

listDocs(): Promise<DocMeta[]>
addDocument(meta: Omit<DocMeta, "id" | "chars" | "indexed" | "uploadedAt"> & { id?: string }, text: string | null): Promise<DocMeta>
  // chunk text with docs/chunk.chunkText and insert into doc_chunks + doc_fts; indexed = text ? "full" : "metadata"; always index name+folder.
deleteDocument(id: string, actor: string): Promise<DocMeta | null>   // caller deletes the R2 object
getDocument(id: string): Promise<{ meta: DocMeta; text: string | null } | null>
searchDocs(query: string, limit?: number, opts?: { includeEmailed?: boolean }): Promise<SearchHit[]>    // FTS5 bm25; sanitise query into OR'd quoted terms with prefix * (adjacent terms also as exact phrases); never throw on odd input; emailed attachments excluded unless includeEmailed
resetSimulated(actor: string): Promise<{ threads: number; approvals: number; tickets: number }>   // demo reset

listContacts(role?: ContactRole): Promise<Contact[]>
upsertContact(c: Omit<Contact, "id"> & { id?: string }, actor: string): Promise<Contact>
deleteContact(id: string, actor: string): Promise<void>

chat(text: string, actor: string): Promise<ChatMessage>            // assistant reply; uses ai/agent-loop.runAgent with this agent as ToolHost
getChat(): Promise<ChatMessage[]>
resetChat(actor: string): Promise<void>                              // clears chat + llm_history

listActivity(limit?: number): Promise<ActivityEvent[]>
listMemory(): Promise<MemoryNote[]>
addMemory(text: string, source: string): Promise<MemoryNote>
deleteMemory(id: string): Promise<void>

seed(data: { docs: { folder: string; name: string; text: string; scope: "building" | "company"; sample: boolean }[]; contacts: Omit<Contact, "id">[]; memory: string[] }): Promise<{ docs: number; contacts: number }>
  // idempotent (skip if meta 'seeded' set). Writes each doc to R2 at r2Key = `${id}/${folder}/${name}` (mime text/markdown) and indexes it.
```

The agent implements `ToolHost` (Module B) by delegating to the methods above.

## Module B: `worker/ai/*`

`worker/ai/client.ts`
```ts
export function aiProvider(env: Env): AiProvider                   // { kind: "anthropic"|"gateway"|"workers-ai"|"off", requested, models, label, note }
export function aiOnline(env: Env): boolean                       // aiProvider(env).kind !== "off"
export function makeClient(env: Env): Anthropic                   // anthropic: apiKey explicit (AI Gateway baseURL if CF_ACCOUNT_ID && AI_GATEWAY_ID); gateway: unified billing (cf-aig-authorization, Anthropic credential headers stripped); maxRetries 2, timeout 90_000
export function modelFor(env: Env, use: "agent" | "triage"): string // env.MODEL_AGENT / MODEL_TRIAGE with defaults claude-sonnet-5-5 / claude-haiku-5-5
```
Use `client.messages.parse` + `zodOutputFormat` (`@anthropic-ai/sdk/helpers/zod`) for structured output.
**Never** force `tool_choice` to a specific tool (400 on Sonnet/Opus 5.5). No temperature/top_p (rejected by 5.x).
Keep `max_tokens` ≤ 16000. Keep system prompt + tools byte-identical across a conversation; history append-only (push full `res.content`).

`worker/ai/triage.ts`
```ts
export interface TriageInput { property: PropertyProfile; channel: Channel; fromName: string | null; fromAddress: string; subject: string; text: string; context: SearchHit[] }
export async function triageMessage(env: Env, input: TriageInput): Promise<Triage>  // Claude if online (on any failure fall back to rules, engine "rules"); untrusted text wrapped in <message> tags; detects prompt injection
export function rulesTriage(input: TriageInput): Triage                              // deterministic keyword rules, engine "rules"
```
Rules must at least get these right: burst pipe / water pouring / flooding / leak through ceiling → maintenance P1 plumber (+ insurer); fire/smoke/gas/sparking → P1 emergency_services; lift stuck → P1; levy/contribution/invoice/arrears → levies P3 accounts; s110/certificate/settlement/disclosure → sales_disclosure P2 accounts + statutoryDeadline "s110: within 14 days of fee paid"; noise/parking/pet/smoking → bylaws_conduct P3; renovation/air-con/approval → owner_approval P3 council; AGM/EGM/minutes/proxy → governance P3; "ignore previous instructions" / "you are an AI" / "system prompt" → suspectedPromptInjection true, needsHuman true, replyNeeded false.

`worker/ai/drafting.ts`
```ts
export interface DraftInput { property: PropertyProfile; companyName: string; thread: Thread; messages: Message[]; triage: Triage; host: ToolHost; instructions: string | null; to: { address: string; name: string | null }; purpose: "reply" | "dispatch"; ticket: Ticket | null; contractor: Contact | null }
export interface DraftResult { subject: string; body: string; citations: Citation[]; rationale: string; engine: "claude" | "template" }
export async function draftReply(env: Env, input: DraftInput): Promise<DraftResult>
```
Claude path: runAgent with toolset "draft" (search/read docs, list contacts) and a final `save_draft` tool ({subject, body, cited_doc_ids, rationale}); citations built from the cited docs' search snippets. Template path (no key / failure): safe template using triage.safetyNotice + top doc snippet. Replies are signed "<staff team> | <COMPANY_NAME>, on behalf of the strata company for SP <n>". Never promise liability, insurance outcome, or excess; never invent phone numbers that aren't in the docs/contacts.

`worker/ai/agent-loop.ts`

Chat tools: search_documents, read_document, list_contacts, list_tickets, list_threads, create_ticket, remember, draft_reply (creates an Approval, never sends). Draft tools: search_documents, read_document, list_contacts, save_draft. `history` is the Anthropic `MessageParam[]` (JSON) persisted by the caller.

`worker/ai/prompts.ts`: `propertySystemPrompt(profile, companyName, memory: MemoryNote[])`, `chiefOfStaffSystemPrompt(companyName)`, plus the triage system prompt. Include WA strata guidance (responsibility rules, emergency first-reply checklist, s110/s107 deadlines) from `docs/strata-wa-notes.md`.

## Module E: `worker/index.ts`, `worker/auth.ts`, `worker/api.ts`

Default export `{ fetch: app.fetch, email(...) } satisfies ExportedHandler<Env>`; also `export { PropertyAgent } ...; export { ChiefOfStaffAgent } ...`.
- email(): `routeAgentEmail(message, env, { resolver: createIkonEmailResolver(...), onNoRoute: m => m.setReject("Unknown recipient") })`.
- Auth: login with `{ passcode, name }` → if `AUTH_REQUIRED !== "false"`: compare with `HUB_PASSCODE` (constant-time), set cookie `ikon_session` = base64url(payload).hmac (HMAC-SHA256 with SESSION_SECRET ?? HUB_PASSCODE), payload `{ n: name, exp }`, 12h, HttpOnly, Secure (except http://localhost), SameSite=Lax. If AUTH_REQUIRED==="false" every request is staff "Demo".
  Off localhost, login answers 503 unless SESSION_SECRET is set and HUB_PASSCODE has at least 12 characters, and 429 after 10 attempts a minute from one IP. Tokens whose `exp` is more than 12h (+5 min) ahead are rejected. Sessions are stateless: rotate SESSION_SECRET to sign everyone out. Put the pilot behind Cloudflare Access.
- `/agents/*` upgrades with an `Origin` other than the hub's own are refused (403).
- `/agents/*` → `routeAgentRequest(req, env, { onBeforeConnect, onBeforeRequest })` both reject (401) without a valid session; only `property-agent` and `chief-of-staff-agent` classes allowed; property name must be a known id.
- All `/api/*` except `/api/login`, `/api/session`, `/api/health` require a session. Mutating routes require `Content-Type: application/json` (or multipart for upload) as CSRF mitigation.
